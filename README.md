# Big A Radar

个人A股热点量化看板。当前版本为本地React原型，使用贴近真实接口结构的模拟数据，暂不连接行情供应商或真实交易账户。

详细架构、数据模型、接口契约和实施路线见 [TECHNICAL_PLAN.md](./TECHNICAL_PLAN.md)。

## 本地运行

项目要求 Node.js 22.13 或更高版本。

```bash
npm install
npm run dev
```

默认地址为 `http://localhost:3000`。

## 当前页面

- 盘中、1—3日、5—10日预测周期切换；
- 热点题材排名及催化摘要；
- 题材传播强度；
- 候选股票及可解释评分；
- 新闻证据链和数据源健康度。
- 四个左侧Tab均可切换；
- 可按日期和运行批次读取本地历史JSON快照。

## 数据流水线

```bash
npm run pipeline
```

每次运行会写入：

- `public/data/snapshots/YYYY-MM-DD/HH-mm-ss/`：永久历史快照；
- `public/data/latest/`：最近一次完整数据；
- `public/data/index.json`：供前端历史选择器读取的索引；
- `public/data/manifest.json`：当前批次状态与文件映射。

流水线采用临时文件加重命名的方式更新JSON，失败时不会写入半截文件。目前数据提供器仍为演示实现，后续接入Tushare、Wind或Choice适配器后替换数据采集环节。

模拟盘使用独立的 `portfolio.json` 保存纯模型账户、人工增强账户、持仓、订单、成交、净值和下一交易日计划。15:35产生的研究信号只允许进入下一交易日计划，不使用当日收盘价倒推成交。

### 每日收盘模拟与复盘流程

1. 收盘后先运行 `npm run pipeline:carry-symbols`，导出待执行计划、现有持仓和未完成 1/3 日结算信号所需的报价代码。
2. Longbridge 全市场扫描和热点深度报价完成后，额外获取这份清单的精确报价；保留提供方时间戳，并写入 `provider-data/longbridge-latest.json` 的 `carryQuotes`。趋势样本至少获取61根前复权日线，计算 `ret10`、`ret20`、`MA20`、`MA60`、MA20五日斜率、ATR20占比、20日平均成交额、量比和横截面动量百分位；同时用宽基指数生成 `marketRegime`。
3. 仅当 CN 市场为 `Closed` 且主报价、`carryQuotes` 都完整带时间戳时运行 `npm run pipeline:real`。
4. 管道将前一交易日计划按本交易日开盘价（加滑点和手续费）模拟成交，再按本交易日收盘价估值；缺报价会记录 `SKIPPED`，不会静默丢弃。
5. 收盘信号写入 `review.json` 的 `dailySignalReview`，在后续收盘以“下一交易日开盘入场”的口径结算 1 日和 3 日表现。
6. 所有数据与归档校验通过后，提交本次流程代码、provider input、`public/data/latest`、`manifest.json`、`index.json` 和新快照目录，并推送当前分支；校验失败时不得提交或推送。

### 回调影子观察

- “趋势回调”要求 `ret10 >= 5%`、`-4% <= ret1 <= -0.5%`、趋势效率至少0.2且量比不超过1.5。它只进入复盘，并按次日开盘、1日/3日收盘结算；在完成样本外验证并获得明确批准前，不生成买单，也不参与新策略的持仓延续判断。

### 风险感知趋势策略

- 真实模型账户使用 `risk-aware-trend-v0.7.0`；热点榜只展示，不再自动生成买单。
- 买入池要求：宽基指数 `close > MA20 > MA60`；个股20日收益5%—25%、单日涨跌-3%—4%、量比0.8—2.0、ATR20不高于5%、20日平均成交额至少2亿元，并满足 `close > MA20 > MA60` 且MA20向上。负向异动不能触发买入。
- 次日开盘相对信号收盘跳空必须在-2%—2%；旧策略买单、越界跳空、行业仓位超过12%或无效报价均明确记录为 `SKIPPED`。
- 正常总仓位上限40%、单票5%、行业12%、每日最多新增2只；单票按账户0.35%风险预算和ATR止损距离定仓。
- 回撤达到3%或单日亏损达到1.5%进入 `RISK_OFF`，暂停买入并把目标仓位降至20%；回撤达到5%进入 `HALT`，只允许减仓。止损、5日时间止损、10日最长持有和8%盈利后的ATR移动止盈均优先于热点排名。

### 五个 Tab 的每日刷新门禁

每个真实收盘批次必须同时刷新“热点雷达、候选股票、新闻证据、模型复盘、模拟盘”五个 tab 对应的 JSON。五个 payload 都会写入当前 `snapshotId`、更新时间、来源时间和 `status: refreshed`；管道在归档前验证雷达有收盘报价、候选池有完整覆盖、证据链已生成、复盘有日更台账、模拟盘有当日净值与下一交易日计划。任一项不通过，整批停止，旧 latest 保持不变，也不得提交或推送。

页面中的证券、价格、分数和事件均为演示数据，不构成投资建议。
